# Goal：补齐文件管理器核心能力，达到成熟可用的插件式产品标准

- 目标：以当前页面效果与现有实现为基准，补齐文件管理器在本机场景的核心缺口，使插件能实际承担浏览、组织、操作、管理的主要职责；仅本机，不打包、不发布、不分发。
- 边界：43 条 wire 命令与 25 个工具不变；不引入终端、agent 会话、外部交付；新 UI 沿用现有 Finder 风格与双语文案。

## 缺口清单（对照成熟文件管理器核心能力审计）

| # | 能力 | 现状 | 动作 |
|---|---|---|---|
| 1 | 列表内拖拽移动／复制到文件夹 | 无（只有外部文件拖入上传） | HTML5 拖拽：条目拖到文件夹上移动，按 Alt／⌥ 复制；目标高亮、Esc 取消、拖到空白回到当前目录；复用 `move_batch`／`copy_batch` |
| 2 | 多选汇总信息 | 状态栏只有数量 | 状态栏显示已选总大小（多选含文件夹按已知条目大小合计） |
| 3 | 打开废纸篓 | 后端 `open_trash` 未接线 | 「更多」菜单 + 空白右键入口，`system()` 门控 |
| 4 | 长列表翻页 | 只有「加载更多」按钮 | 滚动接近底部自动加载（保留按钮兜底） |
| 5 | 新建／上传后的定位反馈 | 操作后无选中 | 新建与单文件上传完成后选中新条目并滚动到可见 |
| 6 | 预览详情创建时间 | 只有修改时间 | 元数据区补「创建时间」（`entry.btime` 已返回） |

## 验证方式

- 每项补 Node 单测或页面桩测试（拖拽判定逻辑、汇总计算、自动加载触发）。
- `npm run check` 全量通过。
- 隔离回环服务 + 真实 Chromium 回归：拖拽移动／复制（含 Alt 与取消）、自动加载、废纸篓入口、汇总、创建时间、新建后选中。
- 文档同步 README／PLUGIN_CONTRACT／ROADMAP。
